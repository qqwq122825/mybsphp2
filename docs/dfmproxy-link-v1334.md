# DFMProxy v133.4：一个开关、一个地址

## 使用

1. 授权后台 → 软件配置 → 代理联动，打开「启用代理联动」。
2. 开关自动保存并生成完整 HTTPS 同步地址，点击「复制地址」。
3. DFMProxy → 设置 → 授权系统联动，粘贴地址，启用后点击「保存并同步」。
4. 首次立即同步，之后固定每 30 秒同步；不填写 AppID、密钥、节点或间隔。

后台不再显示账号查询、凭据列表、权限选择、节点信息和额外保存按钮。
关闭后保留原地址，再次开启继续使用。原客户端登录入口和手动添加的代理用户不受影响。
卡密模式下账号＝密码＝卡密；卡密到期后自动删除对应 DFMProxy 用户并断开连接，后台卡密与历史保留；续期后恢复。
详细参数的用户下拉框只列出手动用户。

## 地址与同步接口

- 地址仍是 `/lk_` 加 32 位密码学随机十六进制字符（128 位随机量），每个应用独立生成。公开站点 URL 来自 `APP_URL`，应配置为实际 HTTPS 域名。
- **完整地址就是同步凭证**。只有管理员页面显示，不公开、不放进截图/工单/日志分享。保持后台登录权限、TLS、禁止缓存；URL 不应被当作普通公开链接。
- DFMProxy 仅向该完整地址 POST JSON `{"action":"sync"}`，不访问根路径、不追加 `/api`、不跟随重定向、不附带额外密钥。空 JSON 正文也按 sync 处理；GET 不返回账号。
- 保留旧版 bearer token 的兼容校验：若请求主动携带旧 token，则仍验证它；新版无需提供。旧 node_id 绑定不再限制同步，更换代理工具后只需填地址。
- 旧数据库字段保留，**本次简化没有新增数据库迁移**。旧客户端的请求结构继续兼容，发布时先更新授权服务器，再更新 DFMProxy。
- 首次新建联动保持原默认重放权限，切换开关不重置已有权限。旧管理端的地址轮换接口保留兼容，但不再占用简化页面。

## CDN

CDN 精确匹配生成地址的完整路径，允许 POST 机器请求、免浏览器挑战、禁用缓存，保留流量防护及限流。根路径的现有规则保持不变。地址是 Laravel 路由，不创建磁盘目录。

CDN/Nginx 访问日志包含秘密路径，应限制访问和保留期限；有固定出口 IP 时可额外限制来源。接口按来源限流 60 请求/分钟。

## 过期与异常

协议保持 `dfmproxy-link-v1`。返回完整用户快照、应用标识、服务器 Unix 秒时间和最长 300 秒离线租约；客户端原子替换快照，缺失用户撤销访问。用户到期时间优先于离线租约，程序重启后缓存只供展示，首次成功同步前不放行。网络异常不清空手动用户。

每个用户包含 subject_id、相同的 username/password、label、expires_at、status、perm、allow_multi=false。仅同步已激活卡或软件账号；账号充值模式继续使用独立代理码作为账号及密码。冻结/撤销会停止代理访问；空到期时间、积分卡不视为永久有效。完整快照上限 10,000 主体，客户端响应上限 8 MiB，超限报错而不提交截断结果。

## 发布和验证

- 当前生产服务器已安装独立 `composer2`（2.10.3）。旧 `/usr/bin/composer` 2.0.14 在重建类加载表时会漏掉枚举，避免用它执行部署命令。
- 本次仅改已有类、模板、前端和客户端，没有新增 PHP 类或依赖；部署源码后刷新配置/视图缓存即可，不必为此重建 Composer 加载表或更新数据库。
- 项目目前尚未集成自动下载 Composer 的部署脚本。换服务器时需先检查 PHP/扩展和兼容的 Composer；依赖按 `composer.lock` 安装，不在生产执行无目标的 `composer update`。
- `public/build` 未纳入 Git。Vue 界面使用 `npm ci && npm run build` 构建后整目录发布。软件配置页校验构建版本、manifest 摘要和依赖文件；只更新源码、旧资源或缺失资源时，使用同样精简的服务端表单，不显示空白标签。
- PHPUnit 在独立 MySQL 测试库 `mybsphp_test` 执行。覆盖 URL-only 接入、按应用隔离、旧绑定兼容、启停、过期、续期、隐藏凭据以及原生/Vue 表单切换。
- DFMProxy 测试覆盖仅地址设置、固定 30 秒、POST 无额外凭据、精确到期删除、离线边界、手动账号不受影响及详细参数下拉框过滤。Windows 实际运行由用户验收。
