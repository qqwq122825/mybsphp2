# MyBsPHP2 AI 协作开发流程

## 1. 总原则

1. 先写需求和接口契约，再写代码。
2. 一个任务只解决一个清晰问题。
3. 每个 API 必须同时提交实现、测试和任务日志。
4. 数据库变更必须使用 migration。
5. Legacy 客户端字段位置必须有契约测试。
6. 多个 AI Agent 不同时编辑同一个文件或同一个模块。
7. 主 Agent 负责架构、合并、回归测试和最终记录。
8. 每个大目标完成后设置验收门，不连续堆功能。

## 2. 大目标划分

### G0：调研与架构确认

目标：

- 审阅旧版 PHP 和 iOS 调用。
- 浏览现有 BSPHP 后台，整理页面地图与交互。
- 确认 PHP 脚手架。
- 固定首版范围和 Legacy 返回契约。

验收：

- 框架决策获得确认。
- 页面清单、角色、权限和 API 清单完成。
- 首版排除项明确。

### G1：脚手架与首次安装

目标：

- 创建正式 Laravel 项目。
- 编写 `/install` 安装向导。
- 配置 MySQL、站点、管理员和后台路径。

验收：

- 空数据库可一次完成安装。
- 重复访问安装器进入已安装状态。
- 默认 `/admin` 可在安装时改写。
- 手机与电脑均能完成安装。

### G2：认证与权限

目标：

- 管理员登录。
- 代理登录。
- 用户账户注册/登录。
- RBAC 与代理权限模板。

验收：

- 默认代理缺少删卡、解绑和账户管理权限。
- 越权请求返回稳定错误码。
- 登录限流和 Session 轮换通过测试。

### G3：应用、卡种与手动发卡

目标：

- 应用管理。
- 卡种、批次、卡密生成。
- 单张/批量手动发卡。
- TXT/CSV 导出和发卡记录。

验收：

- 卡密状态流转正确。
- 批量操作具有事务和回滚。
- 代理只能看到权限范围内的数据。

### G4：Legacy v1 协议

目标：

- `/AppEn.php` 网关。
- `api=login.ic`。
- 固定 `arr[0/1/2/3/4/6/8]` 契约。
- 请求/响应编解码适配器。

验收：

- 旧 iOS Fixture 可完成成功、到期、冻结、异机登录测试。
- `arr[2]` 支持真实值、空值和诱饵值。
- `appsafecode` 原样放在 `arr[3]`。
- UTC 每日签名测试固定。

### G5：两种授权模式

目标：

- 卡密直接登录。
- 账户注册/登录。
- 充值卡给账户增加时长或点数。

验收：

- 两种模式共享应用、产品和审计基础能力。
- 充值卡仅消费一次。
- 并发充值保持幂等。

### G6：风险控制

目标：

- 应用级风险策略。
- 登录频率、设备数量和卡密异常规则。
- Observe、Decoy、Block。
- 风险事件后台。

验收：

- 阈值边界测试完成。
- 同一卡密短时多次登录能触发策略。
- Decoy 只替换指定字段。
- 风险开关关闭后保持正常业务。

### G7：后台 UI 与手机适配

目标：

- 参考旧 BSPHP 的信息架构。
- 重新实现管理后台和代理后台。
- 完成响应式交互。

验收：

- 手机端无横向溢出。
- 宽表格切换卡片或可控滚动。
- 核心操作触控区域不少于 44px。
- 页面与权限状态一致。

### G8：回归与发布

目标：

- 完整测试、安装文档、部署文档。
- GitHub 首个版本。

验收：

- 全量测试通过。
- 新安装与升级测试通过。
- 生产配置检查通过。

## 3. 单个 API 的标准开发流程

每开发一个 API，严格按以下顺序：

1. **建立任务编号**
   - 例：`API-LEGACY-LOGIN-001`。

2. **先写契约**
   - URL、Method、认证方式。
   - 请求字段、类型、是否必填。
   - 成功响应和失败响应。
   - Legacy 固定下标。
   - 幂等和频率限制规则。

3. **准备 Fixture**
   - 正常卡。
   - 过期卡。
   - 冻结卡。
   - 首次绑定。
   - 异机登录。
   - 风险阈值边界。

4. **写失败测试**
   - Unit：领域规则。
   - Feature：HTTP 请求。
   - Contract：Legacy 字符串。
   - Permission：权限。
   - Concurrency：幂等/并发。

5. **实现最小代码**
   - Controller 只做输入输出。
   - Service 处理业务和事务。
   - Policy 处理权限。
   - Risk Engine 处理风险决策。

6. **执行测试**
   - 目标测试。
   - 模块测试。
   - 全量回归。

7. **记录日志**
   - 变更文件。
   - 数据库 migration。
   - API 契约变化。
   - 测试命令和结果。
   - 下一任务。

8. **人工验收**
   - 每个任务完成后，在用户当前浏览器中打开对应本机页面并实际操作。
   - UI 任务检查 1280px 桌面端与 390px 手机端；涉及表格时增加 768px。
   - API 任务先自动检查 JSON，再将浏览器停留在对应的用户可见页面。
   - 截图或结构快照写入任务日志，禁止只以 HTTP 200 代替页面验收。
   - 旧客户端 Fixture 检查。

## 4. AI Agent 分工

最多四个并行角色：

| 角色 | 负责内容 | 文件边界 |
|---|---|---|
| 主 Agent | 架构、任务拆解、合并、回归 | 全局协调 |
| 后端 Agent | 单一 Domain/API 实现 | 指定模块 |
| 测试 Agent | Fixture、Unit、Feature、Contract | `tests/` |
| UI Agent | 单一页面组、响应式检查 | `resources/`、前端资源 |

规则：

- 同一时间每个文件只归一个 Agent。
- 子任务必须有明确输入、输出和测试命令。
- Agent 完成后由主 Agent 复查，不直接视为完成。
- 数据库 migration 按编号串行合并。
- Agent 发现契约问题先写日志，不自行改变协议。

## 5. 测试层级

### Unit

- 到期计算。
- 卡密状态机。
- 账户充值。
- 每日签名。
- 风险阈值。
- 权限判定。

### Feature

- 安装流程。
- 管理员登录。
- 应用、卡种、卡密 CRUD。
- 手动发卡。
- 账户注册、登录与充值。

### Contract

- `AppEn.php` 外层格式。
- `login.ic` 竖线位置。
- `arr[2]` 空值位置不偏移。
- `appsafecode` 原样回传。
- 旧错误码映射。

### Security Regression

- 重放时间窗口。
- Nonce 重复。
- 同卡多设备。
- 短时间高频登录。
- 代理越权。
- 后台路径变更。
- Session 固定和 CSRF。

### UI

- 390px、768px、1280px 三档。
- 登录、安装、表格、弹窗、批量操作。
- 键盘操作和焦点可见。

## 6. 完成定义

任务标记完成必须同时满足：

- 契约已写。
- 实现已完成。
- migration 可重复执行。
- 目标测试通过。
- 全量回归无新增失败。
- UI 任务有截图或浏览器检查记录。
- 每个任务都有浏览器实际打开记录，交付时停留在便于用户检查的页面。
- `DEVELOPMENT_LOG.md` 已更新。
- 相关文档已同步。
