# MyBsPHP2 日志、审计与脱敏契约

> 任务：W1-5
> 状态：已确认

## 1. 普通运行日志

每个 HTTP 请求共享以下日志上下文：

- `request_id`：26 位 ULID，与响应头及 JSON `meta.request_id` 相同。
- `method`：HTTP Method。
- `path`：不包含查询字符串的路由路径。
- `ip_hash`：客户端 IP 的 SHA-256，不写入原始 IP。

请求完成日志只记录状态码和耗时，不记录请求正文、Cookie、Authorization 或响应正文。
普通日志写入异常由日志通道自身隔离，不改变业务响应。

## 2. 敏感字段

以下信息在普通日志和审计前后快照中统一替换为 `[REDACTED]`：

- 主密码、二级密码、密码确认值和数据库密码。
- Authorization、Token、Cookie、Session 标识和 API Secret。
- 应用密钥、客户端密钥、完整卡密、充值卡、序列号。
- `appsafecode`、完整设备标识和其他显式标为 secret 的字段。

嵌套数组使用相同规则。业务代码不得把敏感值拼接进自由文本消息；处理器同时拦截
常见 `password=...` 和 `Bearer ...` 格式。

## 3. 审计日志

审计日志用于后台和代理的高影响操作，统一字段：

- 操作人、角色快照、动作。
- 目标类型、目标 ID、应用 ID。
- `request_id`、IP、User-Agent 哈希。
- 脱敏后的前后快照、原因和结果。
- 26 位公开 ID 与创建时间。

审计记录只追加，不提供更新、软删除和普通删除。后续业务服务应在同一数据库事务内
写入业务数据和审计记录；审计失败时由该业务事务整体回滚。

## 4. 验收门

1. 日志处理器嵌套脱敏测试通过。
2. HTTP 完成日志携带同一个请求 ID。
3. 审计表迁移、写入、脱敏和不可变测试通过。
4. 日志文本中检索不到测试密码、Token、卡密和 Cookie 原文。
5. 全量 PHPUnit、MySQL 与 Pint 检查通过。
