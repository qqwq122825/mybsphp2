# W0-9 · 首版代理层级、余额与提卡规则

## 决策状态

- 状态：已确认
- 日期：2026-07-18
- 适用范围：首版代理中心与管理后台
- 后续实现任务：W3-4、W3-5、W5-8、W10-1 至 W10-8

## 决策

首版代理系统采用以下规则：

1. 只支持**一级代理**，关系为“平台管理员 → 代理”；代理不能创建下级代理。
2. 可以建立多个代理等级，用于定义不同的应用/卡种提卡价格；“代理等级”不代表上下级层级。
3. 代理余额由管理员手动充值或扣减，不接入支付渠道。
4. 代理按其等级对应的应用/卡种价格，从系统库存中自助提卡。
5. 所有金额以整数“分”存储和计算，不使用浮点数。
6. 代理权限采用细粒度权限和最小权限默认模板。
7. 默认禁止代理删卡、解绑设备、管理用户账户、修改价格、充值或扣减余额等高影响操作。
8. 代理默认只能查看和操作自己名下的数据。

## 采用理由

- 一级代理已经覆盖“管理员充值、代理按等级价提卡、线下分发”的首版核心流程。
- 代理等级与组织层级分离，数据模型清晰，也为不同代理价格保留扩展能力。
- 管理员手动充值符合首版不接支付的范围，并可依靠不可变流水进行账务核对。
- 整数分避免小数和浮点计算误差。
- 数据范围、权限检查、数据库事务与审计共同降低越权、超扣和重复提卡风险。
- 多级代理、返佣和下级结算会显著增加账务与权限复杂度，延后实现更利于首版稳定。

## 首版规则

### 1. 代理层级与账号

- 平台可创建多个代理账号。
- 每个代理账号绑定一个代理等级。
- 代理等级可配置名称、状态和排序，本身不形成上下级树。
- 代理账号不包含 `parent_agent_id` 业务能力；即使为未来迁移预留字段，首版也必须保持为空且接口不接受下级代理操作。
- 代理不能创建、编辑、禁用或删除其他代理。
- 管理员可以启用、停用代理；停用后禁止登录和新提卡，历史流水与提卡记录继续保留。

### 2. 金额与余额账本

金额规则：

```text
balance_cents       当前可用余额，整数分
amount_cents        本次变动金额，整数分
unit_price_cents    单张提卡价，整数分
total_cents         unit_price_cents × quantity
```

- 数据库存储使用有符号 `BIGINT` 或等价整数类型，接口传输也以整数分为准。
- 后台可以按元展示，但输入必须转换为分后再校验和落库。
- 禁止用 PHP 浮点数参与余额、单价、总价和退款计算。
- 代理余额不得小于零。
- 每次余额变化必须同时产生一条不可变钱包流水。
- 钱包流水至少记录业务类型、变化前余额、变动金额、变化后余额、业务单号、操作者、原因和时间。
- 已落账流水不修改、不删除；纠错通过相反方向的新流水完成。

管理员手动充值/扣减：

- 只有具备代理余额管理权限的管理员可以操作。
- 每次操作必须输入正整数金额和原因，选择“充值”或“扣减”方向。
- 扣减不得使余额变为负数。
- 重复提交由业务幂等键拦截。
- 余额更新与钱包流水写入必须处于同一数据库事务。

### 3. 代理价格

- 价格维度为“代理等级 + 应用 + 卡种”。
- 每个有效组合配置明确的 `unit_price_cents`。
- 未配置代理价、价格被停用、应用被停用或卡种被停用时，代理不能提取该卡种，不自动回退到管理端零售价。
- 价格修改只影响之后创建的提卡单；历史订单保留成交时的单价和总价快照。
- 代理只有查看适用于自己等级的当前价格权限。
- 管理员负责设置和修改价格，并记录审计。

### 4. 自助提卡事务

代理提交提卡请求时必须包含：

- 应用。
- 卡种。
- 数量。
- 客户端生成的幂等请求号。

服务端流程：

```text
认证代理并检查账号状态
  → 检查 agent.cards.withdraw 权限
  → 锁定代理钱包行
  → 读取并锁定等级价格
  → 校验应用、卡种和价格状态
  → 计算整数分总价并校验余额
  → 锁定足量可售库存
  → 创建提卡单和明细
  → 扣减余额并写钱包流水
  → 将卡密归属到该代理
  → 写操作审计
  → 提交事务
```

- 扣款、流水、库存分配、卡密归属和提卡单必须在同一数据库事务中完成。
- 并发时使用行锁或等效原子约束，防止余额超扣和同一卡密被重复分配。
- 库存不足、余额不足、价格缺失、权限不足等任一条件失败时整笔回滚。
- 同一代理重复提交相同幂等请求号时返回原提卡结果，不再次扣款或分配卡密。
- 提卡完成后，代理可以查看、复制和导出本次获得的卡密；敏感展示行为记录审计。
- 首版不自动向最终用户发货，不创建在线支付订单。

### 5. 默认权限模板

默认允许：

| 权限 | 含义 |
|---|---|
| `agent.dashboard.view` | 查看自己的概览 |
| `agent.profile.view` | 查看自己的资料 |
| `agent.profile.password.update` | 修改自己的登录密码 |
| `agent.prices.view` | 查看自己等级适用的价格 |
| `agent.wallet.view` | 查看自己的余额与钱包流水 |
| `agent.cards.withdraw` | 按有效价格自助提卡 |
| `agent.cards.own.view` | 查看自己提取的卡密 |
| `agent.cards.own.export` | 导出自己提取的卡密 |
| `agent.withdrawals.view` | 查看自己的提卡记录 |

默认禁止：

| 权限/行为 | 首版规则 |
|---|---|
| 删除、批量删除卡密 | 禁止 |
| 修改卡密值、卡种、有效期或状态 | 禁止 |
| 解绑或更换设备绑定 | 禁止 |
| 管理最终用户账户 | 禁止 |
| 查看或修改其他代理 | 禁止 |
| 创建下级代理 | 禁止 |
| 设置代理等级或价格 | 禁止 |
| 给自己或他人充值、扣减余额 | 禁止 |
| 修改应用、协议、风控或系统设置 | 禁止 |
| 查看全局库存、全局账本和全局审计 | 禁止 |
| 绕过库存直接生成卡密 | 禁止 |

管理员可以在后续权限界面中撤销默认允许项；首版不通过给代理增加高影响权限来变相提供管理后台能力。

### 6. 数据范围

- 代理概览只统计该代理自己的钱包、提卡单和已提取卡密。
- 钱包流水查询必须固定加入当前代理 ID 条件。
- 卡密查询只返回 `owner_agent_id` 为当前代理的记录。
- 提卡单和导出只允许访问当前代理创建的记录。
- 应用和卡种仅展示对该代理启用且存在有效价格的部分。
- 不信任请求中的 `agent_id`；代理身份从服务端会话取得。
- 管理员的数据范围由 RBAC 决定，不复用代理查询接口绕过管理端权限。
- 导出任务、缓存键和统计聚合均须包含代理 ID，避免跨代理数据混用。

### 7. 审计与对账

至少记录：

- 代理创建、启用、停用和等级变更。
- 管理员手动充值、扣减和纠错。
- 代理价格创建、修改、启用和停用。
- 提卡成功与失败、卡密查看和导出。
- 权限模板或单个代理权限变化。
- 越权访问、幂等冲突和事务回滚原因。

每日可按以下不变量对账：

```text
期初余额 + 充值 - 扣减 - 提卡支出 + 纠错 = 期末余额
提卡单金额 = 成交单价 × 数量
提卡单明细数 = 成功分配卡密数
```

审计与钱包流水不可由代理删除或修改。

## 验收条件

1. 首版不存在代理创建下级代理的入口、API 或有效权限。
2. 多个代理等级可以为同一应用/卡种配置不同的整数分价格。
3. 未配置有效价格时代理提卡失败且不扣余额、不占库存。
4. 管理员手动充值和扣减均原子更新余额与不可变流水。
5. 代理提卡在一个事务内完成扣款、流水、库存、卡密归属和订单明细。
6. 并发提卡不会使余额为负，也不会把同一卡密分配两次。
7. 相同幂等请求号重复提交不会重复扣款或重复发卡。
8. 默认代理账号没有删卡、解绑、账户管理、价格管理和余额管理能力。
9. 代理只能查看和导出自己的卡密、提卡单与钱包流水。
10. 管理员的充值、改价、权限变化以及代理的提卡和导出均有审计记录。
11. 所有金额计算和持久化均使用整数分，相关单元测试和事务测试通过。
12. 不依赖在线支付、邮箱、短信或验证码服务。

## 延后项

- 多级代理、下级代理管理和层级数据范围。
- 返佣、差价分成、上下级结算和提现。
- 在线支付充值、支付回调和自动对账。
- 授予代理解绑、用户管理或其他高影响权限的扩展方案。
- 余额冻结、授信额度、欠款和账期。
- 代理 API Token、外部系统提卡 API 和 IP 白名单。
