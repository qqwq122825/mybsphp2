# W0-8 · 管理员二级密码决策

## 决策状态

- 状态：已确认
- 日期：2026-07-18
- 适用范围：管理后台登录
- 后续实现任务：W2-8

## 决策

保留 BSPHP 的管理员二级密码能力，但将其实现为**可选的全局功能开关**：

1. 首次安装时默认关闭。
2. 系统设置中可以开启或关闭全局二级密码功能。
3. 全局功能开启后，可以对每个管理员账号单独设置“登录必须验证二级密码”。
4. 二级密码是管理员预先设置的独立静态口令，不是图形验证码、短信码、邮件码或一次性验证码。
5. 二级密码只用于管理后台，不进入用户端、代理端或 Legacy 应用接口。
6. 二级密码不替代主密码；被要求使用二级密码的管理员必须同时通过主密码和二级密码校验。

## 采用理由

- 保留旧版 BSPHP 用户熟悉的后台登录习惯。
- 在后台地址可自定义、登录限流之外，再提供一个可选的独立秘密。
- 允许部署者按实际需要启用，避免首次安装增加不必要的配置负担。
- 采用框架哈希、统一会话、审计和恢复机制，替代旧版可能存在的明文或弱存储方式。

> 二级密码与主密码在同一终端输入时不等同于独立设备上的多因素认证。界面和文档使用“二级密码”，不把它描述为 MFA。

## 首版规则

### 1. 配置模型

首版逻辑配置包含：

```text
admin_secondary_password_enabled    全局开关，安装默认 false
admin.secondary_password_required   单个管理员是否必须验证
admin.secondary_password_hash       独立哈希；未配置时为 null
admin.secondary_password_changed_at 最近修改时间
```

约束：

- 仅当全局开关开启且管理员账号标记为必须验证时，登录流程要求二级密码。
- 把管理员标记为“必须验证”之前，必须先成功设置二级密码。
- 开启全局开关时，系统必须检查所有被标记为必须验证的账号均已有有效哈希。
- 关闭全局开关只停止登录挑战，不自动删除现有哈希和账号级要求，方便再次启用。
- 新建管理员默认不强制使用二级密码，由超级管理员明确配置。

### 2. 存储规则

- 使用 Laravel `Hash` 提供的当前安全哈希驱动存储，优先采用 Argon2id；部署环境不支持时使用框架认可的 bcrypt 配置。
- 主密码哈希与二级密码哈希使用独立字段，不复用、不拼接。
- 数据库、配置文件、日志、异常信息和审计详情中均不记录二级密码明文。
- 修改二级密码时必须生成新哈希；不提供读取、显示或导出原二级密码的功能。
- API/表单响应不返回哈希值。

### 3. 登录流程

```text
访问动态后台入口
  → 校验账号状态与登录限流
  → 校验账号和主密码
  → 判断全局开关与账号级要求
  → 必要时校验二级密码
  → 两项均成功后创建/刷新管理会话
  → 记录成功审计
```

具体约束：

- 任一必需步骤失败都不得创建管理员会话。
- 账号不存在、主密码错误、二级密码错误对外使用统一的登录失败提示，避免泄露账号状态。
- 二级密码字段仅在全局功能启用时出现在登录页；账号级要求在服务端判定。
- 后台入口仍默认 `/admin`，安装时允许重写；入口路径不是二级密码的替代品。
- 登录成功后轮换 Session ID，并沿用 CSRF、SameSite、Secure Cookie 和会话过期策略。

### 4. 限流与锁定

- 主密码和二级密码失败共同计入同一后台登录失败计数。
- 同时按账号标识和来源 IP 限流，避免只更换账号或只更换地址绕过单维度限制。
- 连续失败采用递增等待时间；达到阈值后短时锁定。
- 成功登录后清除对应的短期失败计数，但审计记录继续保留。
- 不用图形验证码、邮件码或短信码作为解锁步骤。
- 限流阈值和锁定时长在 W2-8 实现时配置化，并通过特性测试覆盖。

### 5. 修改、恢复与重置

- 管理员修改自己的二级密码前，必须重新校验当前主密码；已有二级密码时同时校验当前二级密码。
- 超级管理员可以为其他管理员重置二级密码，但必须重新验证自己的主密码，并填写操作原因。
- 重置操作只设置新值或取消该账号的强制要求，不展示旧值。
- 普通管理员无权重置其他管理员的二级密码。
- 唯一超级管理员被锁定时，允许服务器维护者通过本地 Laravel Artisan 恢复命令重置；命令仅允许 CLI 执行，并写入独立审计记录。
- 不采用邮件找回、短信找回、邮箱链接或验证码找回。

### 6. 审计

至少记录以下事件：

- 全局开关开启或关闭。
- 管理员被启用或取消强制二级密码。
- 二级密码设置、修改和重置。
- 主密码或二级密码登录失败（不记录秘密内容）。
- 登录限流、临时锁定和解除。
- 本地 CLI 恢复。

审计信息包含操作者、目标管理员、时间、来源 IP/CLI、请求标识、结果和原因；敏感字段只记录“已变更”，不记录值或哈希。

## 验收条件

1. 新安装系统的二级密码全局开关为关闭状态。
2. 关闭状态下，管理员只需账号和主密码即可登录。
3. 开启全局开关后，未标记为必需的管理员登录行为保持不变。
4. 开启全局开关且账号标记为必需时，缺失或错误的二级密码不会创建会话。
5. 主密码与二级密码均正确时才建立后台会话，并轮换 Session ID。
6. 数据库中只存在独立的哈希，不存在二级密码明文。
7. 登录失败按账号和 IP 受到限流，错误提示不暴露失败发生在哪一步。
8. 超级管理员重置、账号自行修改以及 CLI 恢复均有审计记录。
9. 系统不存在短信、邮件、图形验证码依赖。
10. 覆盖关闭、可选、强制、失败限流、重置和恢复路径的自动化测试全部通过。

## 延后项

- TOTP、硬件密钥、Passkey 等真正的多因素认证。
- 按角色、IP 网段或管理员组批量强制二级密码。
- 二级密码定期过期和历史口令复用检查。
- 异地登录提醒和外部审计平台联动。
