# 卡操作日志（2026-09-27）

## 查看入口

- 后台：控制台 → 系统日志 → 卡操作日志。
- 卡列表：每张卡右侧“查看日志”，直接按卡编号筛选。
- 支持完整卡号/卡标识、卡编号、操作账号、操作内容搜索及时间排序。
- 展示时间、IP、卡号、软件、操作账号/角色、操作内容和发生变化的前后状态。
- 复用 `audit.view` 权限，只读查看、导出当前页或打印，没有删除/清空入口。

## 记录范围

- 管理员、代理的冻结/解冻、删除/撤销、设备解绑、备注/标记、使用状态调整。
- 制卡、发卡、激活、充值、到期时间与并发配置等卡业务字段变动。
- 卡列表批量操作、卡维护、软件用户维护、快捷操作、运营插件。
- 客户端安全流程触发的软件用户冻结，以及封控中心联动解除卡用户冻结。
- 卡维护中的卡种价格/时长修改，会对同卡种已有卡逐张记录其生效配置变化。
- 重复冻结/解冻也保留记录，标注“状态未变化”。

“冻结卡密”与“冻结软件用户”分开标识。设备黑名单本身仍在封控中心/安全日志中管理；卡解冻不等于设备解封。本次没有调整任何冻结、激活、封控规则。

这里只记录已执行的卡操作与业务字段变化；纯查询、导出、心跳时间、失败次数、锁版本不产生卡操作记录。权限拒绝、参数校验失败沿用现有请求/安全日志。全局卡种配置页的独立操作仍沿用原卡种审计，本页的逐卡卡种记录针对卡维护入口。

## 完整性与兼容

- 使用原 `audit_logs` 表，事件 `card.operation`，无新增数据库迁移。
- 卡变更和逐卡日志处于同一个数据库事务；日志落库异常会回滚该卡变更，外层事务回滚也会回滚日志。
- 更新前从数据库加锁读取旧状态，避免陈旧模型导致错误的前状态。
- 批量卡写入使用 `CardOperationLogger::updateCards/deleteCards`，200 条分块且按主键推进；后续代码请勿使用直接 SQL 或 Eloquent 批量写入跳过此入口。
- 账号名、角色及卡身份信息保留快照；管理员/代理同时登录时按当前操作路由选择身份。
- 卡号沿用现有加密存储，并保存查询哈希；物理删除卡后，新增日志仍支持查询及展示。设备原始标识只保存指纹，界面显示已有掩码。
- 兼容已有代理冻结、解冻、解绑和删除日志；同请求同卡的新旧记录在页面去重。旧记录未保存的前后状态显示“历史记录未保存前后快照”，不补造历史。
- 本功能没有数据库级防篡改设计。数据库管理员、系统重置等底层操作仍可影响审计数据，请按原运维方案备份。

## 部署

先备份并核对线上代码版本，再同步本次相关 PHP、路由、Blade 和前端源文件；使用 Composer 2 更新自动加载，构建前端或同步对应 `public/build` 产物，按站点原发布流程更新路由/视图缓存。本功能本身无须迁移，勿执行重置或清空数据命令。

上线后用只读方式查看一张已有卡的历史记录，确认代理账号与操作时间显示正确，再验证卡列表的“查看日志”链接。不要拿真实客户卡做冻结测试。
