# IP 分档封控体系

## 目标

针对单个软件、单个 IP 在短时间内高频调用登录接口的行为，按请求次数自动进入不同档位。策略在后台 **控制台 → IP 封控中心** 中独立配置。

## 默认档位

| 档位 | 默认条件（同一软件、同一 IP） | 动作 |
| --- | --- | --- |
| 正常 | 最近 10 秒内少于 3 次 | 正常校验并返回真实数据 |
| 低级 | 最近 10 秒内达到 3 次 | 业务登录继续并正常返回到期时间；有验证数据时静默替换为诱饵值，无验证数据时只记录 |
| 高级 | 最近 10 秒内达到 5 次 | 上线运行时返回普通服务器故障；调试模式返回明确封控信息；临时封禁 30 分钟 |

计数覆盖账号登录、卡串登录和 Legacy `login.ic` / `login.lg`。注册、充值、心跳不计入登录频率。

统计采用真正的滚动窗口，而不是从第一次请求开始划分固定时间段。每次请求到达时，都重新统计 `(当前时间 - 窗口秒数, 当前时间]` 内的请求，包含本次请求，恰好位于窗口左边界的请求移出计数。例如请求发生在第 0、3、6、11 秒，第 11 秒计算时会保留第 3、6、11 秒三次，因此仍达到“10 秒 3 次”的低级阈值。

## 数据结构

- `risk_policies`：每个软件一套窗口、阈值、低级动作和高级返回策略。
- `ip_risk_states`：IP 当前档位、窗口计数、累计计数和封禁截止时间。
- `risk_events`：只在进入低级/高级档位时沉淀事件，避免每次被阻断都重复写入大量日志。

IP 明文仅用于后台处置，同时保存 SHA-256 值作为唯一索引；设备标识只保存 SHA-256 摘要。

## 后台能力

- 软件策略切换、启停和阈值调整；
- 24 小时命中、低级、高级、正在封禁四项指标；
- 最近命中动态和风险 IP 筛选列表；
- 对单个 IP 执行解除并清零、降为低级、封禁 1 小时、封禁 24 小时或长期封禁；
- 策略修改与人工处置同时写入系统审计日志。

## 运行模式与响应

后台 **系统设置 → 当前模式** 控制对客户端暴露的诊断信息：

- `上线运行`：低级封控保持 HTTP 200、正常业务结构与真实到期时间，不出现“频繁”或封控字段，仅替换验证值；高级封控固定返回 HTTP 503、`SERVER_UNAVAILABLE` 和“服务器暂时故障，请稍后再试”，不返回封控等级、阈值、等待秒数或 `Retry-After`。
- `调试模式`：低级成功数据增加 `risk_control` 判定明细；高级使用软件策略中配置的状态码、错误码和提示，并返回阈值与等待时间。未捕获的 API 异常还会包含异常类型、消息、文件与行号。

调试模式的高级响应示例：

默认返回 HTTP `429`：

```json
{
  "ok": false,
  "error": {
    "code": "ACCESS_TEMPORARILY_RESTRICTED",
    "message": "当前请求过于频繁，请稍后再试。",
    "details": {
      "control_level": "high",
      "retry_after_seconds": 3600
    }
  }
}
```

正式部署在反向代理后时，应确保 Laravel 获取到真实客户端 IP，并将当前模式切换为“上线运行”。
