## 契约/设计

### API

- Method：按资源使用 GET/POST/PATCH/PUT/DELETE；Legacy 统一 POST。
- URL：`/install`、`/{ADMIN_PATH}/api`、`/agent/api`、`/AppEn.php`、`/api/v2`。
- Auth：Install、AdminSession、AgentSession、ClientCredential、LicenseSession。
- Request：关键库存/余额/充值写操作强制 `Idempotency-Key`；Legacy 使用请求指纹补足。
- Response：REST v2 统一 `ok/data|error/meta`；Legacy 固定
  `response.data/date/unix/microtime`。
- Error：稳定机器错误码 + HTTP 状态；Legacy 通过映射返回旧错误码。

### 数据库

- Migration：无，本任务只做接口设计。
- 表/字段：引用 W0-6 数据模型；未新增实现。
- 状态变化：在目录中标注卡密、充值、余额、提卡、风险复核等写操作的事务与终态幂等要求。

## 实现

- 创建 `docs/API_CATALOG.md`。
- 将接口按 W2～W10 任务 ID 映射，列出 Method/Path 或 Legacy `api` 名、认证、用途、
  幂等/限流和关键测试。
- 固定处理器优先级：
  `App Override > Mode Handler > Core Default Handler`。

  `01|xx|{payload}|{appsafecode}|{daily_signature}|1|{expires_at}|1|{device_id}||`。
- 将旧 action 分成首版白名单与明确不进入首版的集合，避免任意文件名分派。
