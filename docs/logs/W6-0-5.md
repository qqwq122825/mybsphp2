# W6-0～W6-5：卡密激活核心链路

**状态：CORE DONE** · **日期：2026-07-19**

## 目标

建立可测试的卡密登录核心 Service，并用纯静态 HTML 模拟客户端完成真实激活。

## API 契约

- `POST /api/v2/demo/activate`
- 输入：应用编码、卡号、卡密口令、设备号和 `appsafecode`。
- 成功输出固定数组位置：
  - `arr[0]` 成功标记 `01`
  - `arr[1]` 客户端识别标记
  - `arr[2]` 应用业务值
  - `arr[3]` 原样返回的 `appsafecode`
  - `arr[4]` UTC 每日签名
  - `arr[6]` 到期时间
  - `arr[8]` 绑定设备号

## 实现

- 卡密查询使用 HMAC lookup，不按明文扫描。
- 首次激活在事务和行锁内计算到期时间、绑定设备并更新状态。
- 相同设备重复调用保持同一绑定关系；不同设备返回冲突。
- 统一处理库存、冻结、过期、作废、应用停用和口令错误。
- 新增 `/demo/activate` 纯静态响应式 HTML，通过 Fetch 调用服务端 API。

## 测试与浏览器验收

- 首次激活、30 天到期、业务值、每日签名、原样安全码和设备字段断言通过。
- 同设备重复激活、异机冲突、库存拒绝和错误口令断言通过。
- 浏览器使用真实手动发出的测试卡完成激活，页面展示 active、到期时间、设备、业务值和 Legacy 数组。
- 390px 静态页与 693px 管理页均无横向溢出。
- 全量工程检查：42 tests / 307 assertions，PHPStan 0 错误，Pint 通过。
