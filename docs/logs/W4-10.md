# W4-10 · BSPHP 风格软件管理与验证数据

## 基本信息

- 日期：2026-07-19
- 状态：DONE
- 负责人：主 Agent
- 依赖：W4 应用管理、W6 激活 Service

## 目标

- 参考当前 BSPHP 后台的软件列表、新增软件和基本配置页面，简化 MyBsPHP2 软件管理。
- 将客户端响应数组 `a[2]` 统一映射到“软件配置 → 验证数据”。

## 本任务范围

包含：

- 新增软件页只保留软件模式、软件名称和软件代号。
- 软件配置页提供长文本“验证数据”，允许地址、文本、JSON 或空值。
- 激活成功时把验证数据原样写入 `a[2]`。
- 软件列表改为 BSPHP 风格的软件卡片，保留配置、充值卡和状态操作。
- 桌面与 390px 手机端浏览器验收。

不包含：

- 库卡列表、库卡增减、用户反馈、支付和邮件模块。
- 风控触发后的诱饵值替换；该能力继续属于 W9。

## 契约/设计

### API

- `POST /{adminPath}/applications`：只接收 `mode`、`name`、`code`。
- `PUT /{adminPath}/applications/{application}`：使用 `verification_data` 保存验证数据。
- `POST /api/v2/{app}/activate`：`payload` 和 Legacy 响应下标 `a[2]` 均取验证数据。

### 数据库

- Migration：`2026_07_19_000008_expand_application_verification_data.php`。
- 继续复用加密字段 `applications.payload_value_ciphertext`，类型扩展为 `LONGTEXT`。
- 新软件默认启用、默认卡密限时权益、默认启用设备绑定，其他参数在配置页维护。

## 实现

- 原版新增页确认只有模式、名称、代号三项；基本配置确认存在“验证数据/超大字符数据”。
- 新增表单与配置表单分开渲染，创建时隐藏设备、返回值和 Legacy 细节。
- `Application::verificationData()` 作为验证数据读取入口。
- `CardActivationService` 不再依赖旧的返回值模式开关，直接读取验证数据。
- 软件列表展示卡总数、已激活、未激活、卡类型和版本号，不加入库卡功能。

## 风险与回滚

- 底层字段名保留以兼容现有迁移和加密 Cast；UI 与请求字段使用 `verification_data`。
- 回滚迁移会把字段恢复为 `TEXT`，回滚前需确认已有密文长度适合旧类型。

## 决策

- 新增软件保持简单；设备和 AppEn 参数只在创建后的配置页出现。
- `a[2]` 默认等于验证数据；没有业务值时保存为空字符串。
- 软件列表不实现库卡相关入口。
