## 目标

- 将旧 BSPHP 数据含义重构为 Laravel 13 + MySQL 8 的正式逻辑数据模型。
- 为 `card_login` 和 `account_recharge` 两种首版模式建立统一的卡密、权益、设备、会话、风控和审计边界。
- 在创建正式 Migration 前固定表职责、关键字段、关系、状态机、事务和唯一性要求。

## 实现

- 对照旧版 `bs_php_admin`、`bs_php_appinfo/appini`、`bs_php_kalei/cardseries`、`bs_php_pattern_car/login`、`bs_php_links_session` 和日志表，拆分新版职责。
- 使用统一 `license_subjects + entitlements` 支撑卡密登录和账户登录，避免复制两套授权业务。
- 使用 Response Profile/Field 表固定 Legacy 数组位置并支持 `arr[2]` 真实、空、诱饵三种结果。
- 设计代理钱包不可变流水、手动发卡头/明细和充值卡兑换流水。
- 设计设备绑定、在线会话、登录事件、风险策略、Nonce、防重放和风险事件。
- 固定卡号 HMAC 检索、加密展示、日志脱敏及不可删除策略。

## 风险与回滚

- 联审结果：W0-8 已确认二级密码新安装默认关闭；W0-9 已确认一级代理、余额不可为负、
  管理员手动充扣和等级价提卡。数据库设计已补齐账号级必需标记与变更时间并保持一致。
- 风险：MySQL 对含 `NULL` 的组合唯一索引有特殊行为，正式 Migration 需使用生成列或不可空活动键并在真实 MySQL 8 测试。
- 风险：旧客户端没有显式 Nonce 时只能使用短窗口请求指纹补充，契约需在 W0-7/W8 固定。
- 回滚：本任务只有设计文档；删除两份新增文件即可，不涉及数据库或运行状态。

## 决策

- 使用 InnoDB、外键和事务，不继承旧版 MyISAM。
- 后台身份与应用账户分离。
- 卡密登录和账户充值共享授权主体、权益、设备、会话和风险表。
- 卡密不删除；使用冻结、过期、消费和作废状态。
- 所有金额按分保存，所有余额变化写不可变流水。
- 发卡、充值、代理扣款、激活和解绑必须具备事务及幂等约束。
- 首版不建立支付、邮箱和验证码相关数据表。
