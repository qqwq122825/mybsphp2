功能与独立性
- 每软件独立：后台 → 软件 → 编辑软件 → 娱乐设置 → 启用同行显示。默认关闭。
- 启动/登录界面只请求娱乐配置，不上报昵称。HUD 开启后，读到有效本地 Pawn、相机和正数队伍 ID，再每 5 秒读取自己的昵称；首次有效昵称触发上报。
- 成功上报后每 600 秒心跳；服务端每条在线记录存活 1200 秒。名单变化最迟在下一次成功心跳反映，不是实时广播。
- 只上报当前安装的随机 UUID 和自己的昵称。其他玩家名字在设备上匹配，不上传到本接口。后台只缓存按软件区分的昵称摘要，不提供明文名单。
- 粉色“同行”（255,105,180）在红色“注视”上方；没有“注视”也显示。新版、旧版、优化简化显示均支持。原有玩家/绘制总开关仍有效；标记不改变瞄准或追踪行为。
- 自己的名字超过 15 秒没有有效更新则清空本地名单并尝试离线；关闭 HUD/锁屏时尝试离线。异常退出依靠 TTL 下线。
- 配置/心跳失败只清空或暂停同行显示，60 秒后重试，不修改卡密、登录会话、授权状态或原来的验证心跳。
- 同名玩家可能误匹配；昵称必须完全一致（去除首尾 ASCII 空白，区分大小写），UTF-8 最长 127 字节。

独立 API
GET  /api/v2/software/{code}/peer-presence/config
POST /api/v2/software/{code}/peer-presence/heartbeat
POST /api/v2/software/{code}/peer-presence/leave
JSON 心跳：{"installation_id":"随机UUID","game_name":"自己的昵称"}
JSON 离线：{"installation_id":"同一随机UUID"}
三个接口不使用卡密/授权会话，也不挂 client.enabled；但使用该软件通信 key 对请求和响应认证。
请求 headers：X-Peer-Time（Unix 秒，容差±300）、X-Peer-Nonce（新 UUID）、X-Peer-Signature。
签名 hex lowercase：HMAC-SHA256(key, METHOD + "\n" + URL路径 + "\n" + 时间 + "\n" + nonce + "\n" + 原始body)。GET body为空。
响应以既有 ApiResponse 包装。X-Peer-Response-Signature = HMAC-SHA256(key, 时间 + "\n" + nonce + "\n" + 原始响应字节)。
重复 nonce 409；无效签名/时钟 401；无效昵称或 UUID 422。接口受每 IP 12 次/分钟限流，配置/心跳正常频率均为 600 秒；共享 NAT 大规模并发可按部署容量调整。
config.data：enabled、heartbeat_seconds=600、ttl_seconds=1200。
heartbeat.data：enabled、heartbeat_seconds、ttl_seconds、peers=[{digest,expires_in}]。
digest = SHA256(UTF8("mtx-peer:v1:"+软件code+":"+规范化昵称))；不返回自己当前 installation 的记录。离线和改名覆盖该 installation 的记录。
昵称摘要只用于显示匹配，不是游戏身份或授权凭证。通信 key 随客户端分发，也不等于用户授权凭据。不要将这个接口视作卡密验证替代品。

2026-10-17 追加：MD5 条件名单协议 v2
- 新客户端心跳增加 roster_protocol=2、roster_md5。首次/清空/失败后的请求发送空字符串。
- 服务器先处理自己昵称的上线/续期并清理过期成员，再按软件生成名单。名单为去重、字典序排序后的 SHA256 昵称摘要，使用单个 LF 连接且末尾无换行；空名单为 ""。
- roster_md5 = MD5(UTF8("mtx-peer-roster:v2:" + 软件code + ":\n" + 名单字符串))，小写32位。时间戳、TTL、条目顺序不参与版本变化。
- 相同：响应 data 含 roster_protocol=2、roster_format="digest-lines-v1"、roster_updated=false、roster_md5、roster_ttl_seconds=1200，不含 roster，也不含 peers。不重新发送名单。
- 不同：roster_updated=true，同时返回 roster 字符串；客户端验证格式、排序/去重、MD5 后原子替换本地名单和 MD5。空字符串也要覆盖旧名单，不能忽略。
- 新增/离线/改名/过期使成员集合改变时，下一次心跳下发完整新名单；纯续期不改变 MD5。名字和 MD5 在同一次心跳上报，无需额外下载请求。
- 本地缓存为内存中的已验证名单+MD5；重启/停止/换名/网络失败/无效响应时一起清空，下一次请求全量。已知空名单仍有有效 MD5，不会反复下载。
- 相同响应也续期整个名单快照的1200秒显示租约；MD5本身不包含租约。网络失败会立即清空显示并60秒后重试；仅回传未更新但客户端没有匹配缓存时也重新拉全量，避免名单丢失后一直空白。
- 服务器每个 installation 仍在1200秒未心跳后过期。v2 本地使用集合快照而非逐人到期时间，离线/过期变化最迟在下一次成功600秒心跳反映；不是实时在线证明。不能仅凭 unchanged 无限使用本地过期缓存。
- MD5只作带宽/缓存版本，不替代现有 HMAC-SHA256 请求/响应认证。服务端仍不下发明文其他玩家名字。
- 兼容发布：旧客户端不带 roster_protocol，继续取得原 peers+expires_in；新客户端连接旧后台可回退原格式。建议先部署后台再更新客户端。
- 当前容量保护仍为每软件4096安装/客户端最多4096条摘要。全量字符串约266KB；未变更响应保持常量大小。不因MD5取消现有容量/响应大小限制。
- 本次追加仅改协议代码，不新增数据库字段；若上一版同行显示还未部署，仍需先运行其 migration。
